二、逐项说明

1. 编辑态行距 6px → 14px

问题：五个字段行只有 padding-top: 6px 且 margin: 0，五行挤成一坨，没有呼吸感。


.ef-row {
  padding-top: 14px;   /* 原 6px */
}

代价（实测）：内容总高 483 → 542px。卡片内容视口固定 410px，所以需滚动的量从 73px 增加到 132px。

2. 只读三块：去底色描边 + 值在上名在下

问题：原来是「灰底 + 描边 + 三栏竖线」三种分隔手段叠一起，压在纸感卡面上很突兀；且它是「名在上、值在下」，和下面所有可编辑行的「名在左、值在右」是两套排版语言。

改法：撤掉灰底和描边，只留两条 1px 细竖线；顺序倒成值在上、名在下，值字号 11.5px → 14px。

3. 只读三块两端对齐，上传地点列加宽

问题：原来 grid-template-columns: repeat(3, 1fr) 三等分，每栏 99px。但三块内容宽度差得很远：

列值最宽标签宽实际需要
编号48px（NO.001）20px~48px
上传地点140px（上海市黄浦区南京东路）40px~152px
入库时长47px（14 天前）40px~59px

结果「上海市黄浦区南京东路」被截成「上海市黄浦区南京…」，而编号那栏还空着。

改法：改成 flex，按内容分配宽度 —— 首末列固定、中间列吃掉剩余空间。


.ef-readout { display: flex; align-items: flex-start; }
.ef-readout__cell:first-child { flex: 0 0 auto; min-width: 78px; }
.ef-readout__cell:nth-child(2) { flex: 1 1 auto; min-width: 130px; }  /* 上传地点 */
.ef-readout__cell:last-child { flex: 0 0 auto; min-width: 72px;
  display: flex; flex-direction: column; align-items: flex-end; text-align: right; }

实测结果：列宽 78 / 148 / 72px，中间列接近原来的 1.5 倍。首块贴左、末块贴右，形成两端对齐；末块内容右对齐。

4. 品牌从下拉改成可输入 + 实时匹配

问题：原来品牌是 <select>，只能在已有 4 个品牌里选，想加新品牌没有入口。

改法：换成 <input>，接入与标签同一套匹配逻辑：

  • 输入时实时匹配「已有品牌里含当前关键字」的，列出 已有品牌 · 霸王茶姬 · 已有 3 件
  • 没有精确命中时给一个 ＋ 新建品牌「xxx」 入口
  • 候选面板用绝对定位浮层，弹出时不会把下面的「收藏日期」整行顶下去
  • 回车选中第一条候选；Esc 只收起面板

数据链路：保存时若品牌不在已有列表，它会成为一个新展示架（首页陈列页多一组），并同步清掉排序缓存 ddj.shelfOrder。

5. 编辑态图片 148px → 128px

配合行距放宽，把图片从 148px 收到 128px 作为折中。只改一个变量，图片的 max-height 是 calc(var(--art-h) - var(--art-pad) * 2) 推导出来的。


.detail-card.is-editing .detail-artwork { --art-h: 128px; }

只读态（非编辑）的图片仍是 168px，未改动。

6. 聚焦色统一为品牌红 #C50405

新增变量，替换原先的橙色 --amber：


:root { --focus: #C50405; }

生效于四处：名称下划线、日期下划线、标签框下划线、备注左侧竖线。候选高亮也用它。

对比度：白底上 6.19:1，达 WCAG AA。

7. 匹配高亮只标命中子串

问题：原来是整个候选词都染红（<em> 包住全名）。输入「霸王」时「霸王茶姬」四个字全红，看不出匹配在哪。

改法：新增 highlightMatch(text, keyword)，只把命中的子串包进 <em>：

输入候选显示
霸王霸王茶姬霸王茶姬
咖咖啡咖啡
茶霸王茶姬霸王茶姬

实现要点：

  • 逐段 escapeHTML，不能先拼 HTML 再转义（否则 <em> 自己会被转义）
  • 用 indexOf 而非正则，避免关键字里的 . * ( 被当元字符
  • 大小写不敏感匹配，但保留原文大小写：peets → Peets Coffee

8. 「＋ 新建」行配色 绿 → 蓝 #2A4DA6

配色演变：#2e7d4f（原深绿）→ #F5D14D（暖黄，对比度仅 1.49:1，字看不清）→ #2A4DA6（靛蓝）。

对比度：白底上 7.75:1，达 WCAG AA，是本轮四个候选里最高的。

9. 补齐 maxlength 与保存兜底截断

发现的缺口：名称有 maxlength=24、品牌有 maxlength=20，但标签输入框完全没有限制 —— 粘贴一整段文字会变成一个超长胶囊把行撑破。

补齐三层：

位置限制说明
#editTagInputmaxlength="12"键盘输入
commitTag()slice(0, 12)兜底：批量分词、点「＋ 新建」都不走 maxlength
saveDetailEdit()名称 24 / 品牌 20兜底：程序化赋值绕过 maxlength

为什么要多层：maxlength 只管键盘打字，管不到 commitTagsFromInput() 一次塞多个词、以及点候选行（值来自 data-* 属性）这两条路。

10. 修 Esc 关闭整张卡导致丢改动 ⚠️ 本轮最重要的修复

Bug：全局有一个 document 级 Escape 处理：


document.addEventListener('keydown', event => {
  if (event.key === 'Escape') closeSheets();   // ← 问题所在
});

用户在品牌/标签框里按 Esc 想收起候选面板时，事件冒泡到这个全局处理，把整张详情卡关掉，未保存的改动全部丢弃；同时输入框失焦，后续打字全部落空。

验证复现：


打茶后:  {v: '茶', h: false}          ← 候选正常弹出
Esc 后:  {activeElement: '', stillEditing: false}   ← 卡片被关、焦点丢失
继续打字: {v: '茶'}                    ← 输入无反应

改法：若焦点在编辑表单内、或候选面板开着，Esc 只收面板不关卡片。


document.addEventListener('keydown', event => {
  if (event.key !== 'Escape') return;
  // ⚠ 编辑态里按 Esc 只应关掉「匹配下拉」，不能把整张详情卡关掉。
  const inEditForm = event.target instanceof Element
    && event.target.closest('#detailEditForm');
  const anySuggestOpen = ['#editTagSuggest', '#editShelfSuggest'].some(sel => {
    const p = $(sel);
    return p && !p.hidden;
  });
  if (inEditForm || anySuggestOpen) {
    hideTagSuggest();
    hideShelfSuggest();
    return;          // 不动卡片
  }
  closeSheets();
});

修复后验证：


Esc 后:  {panelHidden: true, stillEditing: true, active: 'editShelf', cardW: 348}
继续打字: {v: '茶姬', h: false, n: 2}   ← 焦点保留、匹配恢复

四、遗留与说明

  • 编辑态滚动量 132px：行距放宽带来 59px、图片回收省下 20px，净增约 39px。底部有渐隐 +「向下滚动」提示兜底，滚动是明示的。若要进一步压缩，把 --art-h 从 128 继续下调即可（每降 1px，滚动量少 1px，一比一）。
  • 只读态图片仍为 168px，本轮未动。
  • .ef-readout 从 grid 改成 flex：如果后续有代码依赖 gridTemplateColumns，需要同步调整。
  • 品牌输入精确命中时面板会自动收起（refreshShelfSuggest 的行为）：输入「霸王茶姬」正好等于已有品牌时不再弹候选；退一格回到「霸王茶」候选立刻恢复。这是刻意设计，避免"已经选好了还挡着下面"。
  • 只读条保持纵向排布（已定案）：曾评估过「只读条与图片左右并排」，结论是 0.552 比例的竖版纸袋图与 39px 高的横排三栏条无法共存，任何左右排布都会让只读条变成竖排、可读性反而下降。决定不做，继续用「上图片 + 下只读条」，方案页已删除。

  • 编辑态入口：点任意藏品卡 → 点「编辑」
