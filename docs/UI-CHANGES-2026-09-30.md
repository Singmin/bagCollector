## 一、标记已有：流程重构 + 组件化（本轮最大改动）

### 1.1 旧流程的问题

旧实现在 `pages/showcase/index.vue` 的 `markExisting()`：

```
点击 → 立即 createCollectible（feed 信息 + 默认第一个展架）→ 再弹编辑半窗核对
```

缺陷：**入库先于确认**。用户如果直接关掉半窗，收藏已经落库且是默认信息（名字未确认、展架是第一个），产生脏数据且无法撤销。

### 1.2 新流程（方案 A：先核对后入库）

```
点击 → 打开半窗（预填 feed 信息，不入库）
      → 点「确认标记已有」→ 这一刻才 createCollectible → toast 已加入我的收藏
      → 点取消/遮罩/切页 → 什么都不发生
```

### 1.3 抽出共享组件 `components/mark-sheet/mark-sheet.vue`（新建，171 行）

**为什么抽组件**：「标记已有」出现在三处（首页大卡背面按钮、首页大卡右上角 ◎、我的页心愿详情卡 ◎），原来只有首页有半窗、我的页用 ActionSheet 选展架直接入库，交互不一致。抽组件后**一处实现、三处同款**。

| 组件要素 | 说明 |
|---|---|
| Props | `show`（显隐）、`item`（来源 feed 条目）、`wished`（该条目当前是否在心愿袋） |
| Emits | `close`、`saved(source, createdId)` —— 回传来源条目**与新建收藏的 id**（删除标记时需要收藏 id） |
| 打开时 | 拉展架列表（失败则分类留空），预填名称/标签/备注 + 默认第一个展架 |
| 保存 | `commitTags()` 收走未提交草稿 → `claimOfficialBag`（见下方「入库链路」）→ 若 `wished` 则 `removeWishlist` → emit → 关窗 → toast「已加入收藏架」 |
| 重复认领 | 后端回 `CONFLICT`（重启小程序后本地已标记状态丢失、再点一次会命中）→ toast「这只袋子已在收藏架」并关窗 |
| 底栏 | 组件内自行 `setTabBarHidden(show)`（底栏是框架层，页面 z-index 压不住） |
| 样式 | 复用 `styles/edit-form.css`（下划线纸感）+ 自带图区与提示样式 |

**入库链路（2026-09-30 修正）**：保存走 `POST /official-bags/:id/claim`（`dataService.claimOfficialBag`），
半窗里改过的名称 / 分类 / 标签 / 备注作为覆盖值传给后端，不传则用袋子自带内容并默认进「未分类」展架。
~~原先走 `POST /collectibles`~~ 是错的：那是拍照上传流程的接口，只收 name/shelfId（标签备注被丢），
建出的记录无图片、永远停在 `UPLOADING`，而收藏列表只返回 `READY` —— 结果就是「标记了但收藏架永远看不到」
（线上僵尸数据按 `processingStatus='UPLOADING'` 且无 ImageAsset 清理）。
认领接口当场建记录、图片由 worker 在后台复制，复制完成置 `READY` 后才出现在收藏架。

**半窗内容（自上而下）**：
1. 互斥提示（仅 `wished` 时出现）：`♥ 已在你的心愿袋中，确认标记后将自动移出`（引用式：无底色无边框、居中）
2. 图区：无底色居中 `aspectFit`（233rpx 盒 / 196rpx 图 / 柔影 / 占位块）
3. 名称（下划线输入，24 字）
4. 分类（输入 + 候选下拉）
5. 标签（chip 盒：`# 标签` + × 删除 + 内嵌输入）
6. 备注（左侧竖线 + 极浅底文本域）
7. 底部：`取消`（白描边）+ `确认标记已有`（黑底白字）

### 1.4 标记 ↔ 心愿袋 互斥规则

| 当前状态 | 操作 | 结果 |
|---|---|---|
| 未标记、未加心愿 | 点 ◎ | 打开半窗 |
| 已标记 | 点 ◎ / 点「标记已有」 | **弹删除确认**「删除这条收藏？将从收藏架删除『xxx』的记录」（红确认钮），确认后 `DELETE /collectibles/:id`（后端同步解除拥有关系），互斥解除 |
| 已标记 | 点 ♥ | toast「已标记，无需心愿袋」 |
| 已加心愿、未标记 | 点 ◎ | 半窗顶部提示 + 确认后**自动移出心愿袋** |

首页用 `markedMap`（feed id → 收藏 id）、我的页用 `justMarkedMap` 维护该关系。

**认领后的可见延迟**：图片还在 worker 里复制，收藏列表（只返回 READY）可能晚几秒才查到这条新收藏。
收藏架页在认领后的窗口期内（`markClaimPending`，约 20s）自动补刷 3 次（间隔 2s），避免「刚标记完切过来是空的」。

### 1.5 文案

- 取消心愿 toast：~~已取消心愿~~ → **已移出心愿袋**（与收藏架页统一）
- 标记互斥 toast：~~已标记已有，无需加入心愿袋~~ → **已标记，无需心愿袋**（压到一行内）
- 标记成功 toast：~~已加入我的收藏~~ → **已加入收藏架**（记录已建好，图片随后现身）

## 三、拍照上传：两个 Bug 的根因修复

### Bug 1：拍照上传必报错

**根因**：`services/mock-data.ts` 的 `/uploads/policy` 返回 `uploadUrl: ''`，`uni.uploadFile({ url: '' })` 必然失败，抛出「图片上传网络失败」。Mock 从来没有存储后端，这条路径此前从未真正跑通过。

**修复**：`pages/add/index.vue` 的 `submit()` 增加 `USE_MOCK` 分支，跳过 policy / uploadFile / complete 三步，直接用本地临时图路径作为缩略图与展示图创建收藏。真实后端接入后该分支自动失效。

### Bug 2：拍完照「先闪回首页再开编辑页」

**根因**：连续两次 `redirectTo`（拍照页 → 处理页 → 编辑页）。Mock 下处理页首轮轮询立即再跳，两次页面转场叠加，中间瞬间页面栈重建，栈底层的首页 tab 短暂露出。

**修复**：新增 `nextStepUrl(collectible)`，依据创建接口返回的 `processingStatus` 决策：

- `AWAITING_CROP` / `READY` → **直达编辑页**（Mock 恒为此态）
- 其他（真实后端归一化中）→ 仍进处理页等待
