## 一、收藏列表一次取全

### 根因

展架视图（`library/index.vue`）的分组是实时过滤出来的：

```ts
const groups = computed<ShelfGroup[]>(() => {
  return shelves.value.map((shelf) => ({
    ...shelf,
    items: items.value.filter((item) => item.shelfId === shelf.id)
  })).filter((group) => group.items.length);
});
```

而收藏列表接口是分页的（前端 `limit=30`、后端上限 100，按 `addedAt desc` 排序）。品牌一多，首屏 30 条只覆盖「最新」的一部分收藏，落在后面品牌的 `items` 还是空的，`.filter((group) => group.items.length)` 就把这些品牌分组整个过滤掉——表现为「后面的品牌分类及其纸袋/数量不见了」，滚到底触发 `loadMore` 才一个接一个补出来。

### 改动

1. **后端** `apps/api/src/collectibles/collectibles.service.ts`：`list()` 的 `limit` 上限 `100 → 1000`（对齐 `feed` 接口）。
2. **前端** `apps/miniapp/src/pages/library/index.vue`：`query()` 里 `limit=30 → 1000`（一次取全）。

### 影响与兜底

- 收藏是个人数据、量级有限，一次拉全更符合「分组完整展示」的预期；游标翻页（`loadMore` / `fillViewportIfNeeded`）保留作 1000+ 件的兜底。
- 宫格视图仍按 `GRID_STEP=120` 增量渲染，不受「一次取全」影响。

## 二、待观察的次生点（暂未改）

一次取全后，`hydrateThumbnails` 会对**全部**条目调用 `settleThumbnail → loadImageAspect`，其中 `uni.getImageInfo` 会对每张图读一次尺寸。

- 生产环境图片走 CDN，`<image>` 有 `lazy-load`，且 `resolveCollectibleThumbnail` 在 https 下直接返回 URL（不下载），真实收藏量级（几十到几百件）通常没问题。
- 若真机实测发现进页面后图片尺寸回调明显变慢（大量 `getImageInfo` 并发），再单独给 `loadImageAspect` 加并发限流（参照 `services/images.ts` 的缩略图下载队列思路）。
