## 一、10-01：后台管理增强与 API 稳定性

### 1. 官方袋子换图 / 删图（`7ed316a` + `e2b608d`）

- 已拥有的官方袋子开放**换图**与**删图**（此前删除被 `claimedCount > 0` 拦截）
- 放开删除限制：级联清除拥有记录与心愿标记，用户已收藏到自己架子的袋子不受影响
- 后台删除按钮全量可见，红色二次确认

### 2. Fastify 启动崩溃与 DELETE 400 修复（`854b6d5` + `e2b608d`）

- `854b6d5`：改用 `adapter.useBodyParser` 注册 JSON parser，修复 `FST_ERR_CTP_ALREADY_PRESENT` 启动崩溃
- `e2b608d`：admin 前端仅在**有 body 时**声明 `application/json`；API 注册容忍空 body 的 parser 兜底——修复无 body 的 `DELETE`（删品牌/袋子/图片）被 Fastify 以「空 JSON body」400 拒绝
- 错误提示增加 `body.message` 兜底，直接展示后端原始报错

### 3. worker：遗弃上传对账清理（`c353d53`）

新增对账任务，清理**无图片资产的 `UPLOADING` 残留**（只建了记录、图片没传上来的僵尸收藏）。

### 4. 小程序展架袋图（`7d8e94f`）

- 展架袋图统一 `240rpx` 并改 `aspectFit` 防拉伸
- 「标记已有」后不再自动补刷收藏页

## 二、10-02：编辑器流水线改造 + 真实后端联调

> 详细见 `docs/CHANGES-2026-10-02.md`（后端流水线 + 编辑器 UI）、`docs/CHANGES-2026-10-02-real-backend.md`（联调）、`docs/UI-CHANGES-2026-10-02.md`（UI 只读版）。此处为摘要。

### 1. 图像处理流水线拆分（`c693786`）

- `crop`（裁剪/旋转/调色，不调万象）与 `matte`（抠图，调万象）拆成两个端点，避免「只想裁剪也扣抠图费」

- worker 新增 `cropToAsset` / `cropImage` / `writeRenditions`，调色参数由 sharp 落盘
- 迁移 `20260930010000_split_crop_and_matting`

### 2. 图片编辑器 UI 改造

- 裁剪页：纸感白底圆角画布、图标式工具行、比例与旋转同行、调色滑杆常驻、底部 ✕/✓ 圆形钮

- 处理页：失败态新增「重试」「返回编辑」

### 3. 真实后端联调（`38aed88..19a5853`）

### 4. 图片 URL 代理与回退（`2e90327` + `8fb440a`）

## 五、10-04：图片加载提速与首次上传修复

### 1. 图片加载提速（`74d37ca`）

- COS 上传加 `Cache-Control: immutable` 缓存头（key 带 `v{n}` 版本）
- 新增 `ASSET_URL_MODE`（`proxy` / `public`），`public` 走 COS/CDN 直连
- 小程序缩略图下载并发上限 4→10；library 分两批入队（首屏优先）；showcase 改按需下载（渲染窗口 ± 缓冲）
- crop 页预览从 canvas 改为 DOM/CSS 渲染，新增加载态蒙层
- 同步 `.env.example`、`infra/.env.deploy.example`、`docs/IMAGE_PIPELINE.md`

### 2. 首次上传未裁剪自动全幅裁剪（`75ddbe9`）

首次上传完成后状态停在 `AWAITING_CROP`（等用户裁剪），此时只有标准图、没有展示图，而收藏架只返回 `READY`——用户不裁剪直接「确定添加」会让这条收藏永远看不到。

- 保存时若状态为 `AWAITING_CROP`，自动做一次**全幅裁剪**（参数全默认，画面不变、免费不占抠图配额），产出展示图/缩略图并推进 `READY`
- 轮询等待就绪（30s 超时，1s 间隔）后再跳收藏架
- 顺带放大完善信息页预览图区（306rpx → 480rpx）

## 八、部署注意事项汇总

1. **改 Prisma schema 务必先跑迁移**：10-01 以来多次加字段/枚举（调色、`quantity`/`visibility`、`sourceOfficialBagId`、审核字段等），CI/生产用 `migrate deploy` 只应用已存在的迁移文件，本地能跑不代表线上能跑。
2. **改 schema 后需重新生成 Prisma Client**：未执行 `pnpm db:generate` 前，api/worker 构建会报 `Property does not exist on PrismaClient`。
3. **认领引用模式转换**：api 容器内执行 `node scripts/migrate-claims-to-reference.mjs`（默认 dry-run），确认后加 `--execute`；先用 `analyze-claims.sql` 看分布，执行后用 `verify-claims-migration.sql` 验证三项为 0。
4. **图片 URL**：`API_PUBLIC_URL` 漏配会自动回退 COS 直链；`ASSET_URL_MODE=public` 走 COS/CDN 直连。
5. **CI 部署**：发布流程当前回退到服务器现场构建（`854b6d5`），Docker 构建已切 npmmirror。
