# 腾讯云凭据获取教程（COS 桶 / 地域 / CAM 密钥）

> 目标：从零把 BagCollect 需要的腾讯云配置拿到手，填进 `.env`，并验证通。
> 全程在控制台点，不需要写代码；熟练约 20 分钟，其中实名认证可能需等待审核。
> 相关文档：[数据万象抠图实施方案](TENCENT_CI_MATTING.md)、[微信小程序运行与发布](WECHAT_NATIVE.md)

## 0. 先看要拿什么

| 要拿到的东西 | 对应变量 | 长什么样 | 从哪拿 |
|---|---|---|---|
| 桶名 | `COS_BUCKET` | `bagcollect-1250000000`<br>（自定义名 + `-` + APPID） | COS 控制台 → 存储桶列表 |
| 地域 | `COS_REGION` | `ap-guangzhou` | 同上。控制台显示中文「广州」，要转成英文代码 |
| 密钥对 | `COS_SECRET_ID`<br>`COS_SECRET_KEY` | `AKIDxxxxxxxxxxxxxxxx`<br>32 位随机串 | CAM 控制台 → 子用户 → API 密钥 |
| APPID（顺带记下） | — | `1250000000` | 桶名的后缀部分，也是权限策略里要用的账号 ID |

**顺序有依赖**：先有桶，才能拿到桶名和地域；先有桶和万象绑定，密钥才有意义。所以下面按控制台顺序走，不要跳步。

## 1. 注册并实名认证

1. 打开 <https://cloud.tencent.com/> 注册腾讯云账号。
2. 右上角「控制台」→ 按提示完成**实名认证**（个人主体用身份证，需绑微信或银行卡校验）。
3. 实名完成前，COS 和其他产品都无法开通。

> 建议用与微信小程序主体相同的身份做实名，后续审核、备案信息才对得上。

## 2. 开通对象存储 COS

1. 打开 <https://console.cloud.tencent.com/cos>。
2. 首次进入会提示开通服务，点确认即可。COS 本身有免费额度，创建桶不收费。
3. 点「创建存储桶」。**这张表逐项按下面填，尤其注意数据冗余策略：**

| 表单项 | 怎么填 | 填错的后果 |
|---|---|---|
| 名称 | 只填自定义部分，如 `bagcollect`。系统会**自动追加 `-你的APPID`**，输入框右侧会以灰字显示，不要自己再写一遍后缀 | 填成 `bagcollect-1250000000-1250000000` 会让后续一切请求都失败 |
| 存储桶地域 | 选广州这类支持抠图的地域，对照见第 3 节 | 抠图接口直接不可用，且地域创建后不可改 |
| 请求域名 | 保持默认。控制台提示的「默认域名存在安全风险」不影响功能，可后续再配自定义域名 | 无 |
| **数据冗余策略** | **必须选「单 AZ 存储」** | **选成多 AZ 会让数据万象图片处理整体不可用，而且多 AZ 特性开启后无法关闭 —— 只能删桶重建** |
| 访问权限 | 选「私有读写」 | 开公有读会让别人的图可被匿名访问 |
| 存储桶标签 | 留空 | 无 |

> **多 AZ 是本项目最贵的一个勾。** 官方《图片处理概述》与《图片基础处理》都写明「图片处理目前暂不支持多 AZ 存储桶」，而它又是唯一一个**开错了无法回退**的选项。创建前请确认「单 AZ 存储」是选中状态。

## 3. 开通数据万象并绑定存储桶 ← 最容易漏的一步

抠图能力由**数据万象（Cloud Infinite，CI）**提供，它依附于 COS 桶。只开通 COS 是不够的。

1. 打开 <https://console.cloud.tencent.com/ci>，按提示**开通数据万象服务**。
2. 开通过程中会弹窗要求**创建服务角色并授权**（形如 `T-CI-ServiceRole`，用途是让万象读写你的 COS）。
   **必须点同意**。不授权的话，后面抠图会返回权限错误，而且报错信息不会直接告诉你少了这一步。
3. 进入「存储桶管理」→ 点「绑定存储桶」：
   - 选择**绑定已有 COS 存储桶**（第 2 步没建桶的话这里也可以直接新建一个）；
   - 选一个 COS 桶，确认绑定。

绑定时的三个硬性要求：

| 要求 | 说明 |
|---|---|
| **地域** | 智能抠图只在部分地区可用，见下方对照表，选错了接口直接不可用 |
| **不能是多 AZ 存储桶** | 官方明确「图片处理暂不支持多 AZ 存储桶」。多 AZ 开启后无法关闭，建桶时选错只能删桶重建，见第 2 节 |
| **访问权限用私有读写** | 本项目全部走签名 URL，桶不要开公有读 |

抠图支持的地域（2026-09 官方使用限制）：

| 控制台显示 | `COS_REGION` 取值 | 支持抠图 |
|---|---|---|
| 北京 | `ap-beijing` | ✅ |
| 上海 | `ap-shanghai` | ✅ |
| 广州 | `ap-guangzhou` | ✅ **本项目默认** |
| 成都 | `ap-chengdu` | ✅ |
| 重庆 | `ap-chongqing` | ✅ |
| 南京 | `ap-nanjing` | ✅ |
| 中国香港 | `ap-hongkong` | ✅ |
| 新加坡 | `ap-singapore` | ✅ |
| 法兰克福 | `eu-frankfurt` | ✅ |
| 深圳 / 清远 / 天津 / 东京 / 首尔 等 | — | ❌ 不支持抠图，只能存文件 |

> 桶的地域**创建后不可更改**。如果已经建在了不支持抠图的地域，只能新建一个桶并迁移。

### 抠图在控制台上没有「开通」开关，别找了

这是最容易让人卡住的一点：如果你在控制台里翻「图片处理 → 图片处理使用规则」想找抠图，**那里永远不会有**。那一页只有基础图片处理、图片压缩、盲水印、原图保护这些**开关式**能力。

抠图属于数据万象的**内容识别（AI）**体系，是纯按调用付费的 API。它的前提条件只有两条 ——「已开通数据万象服务」+「存储桶已绑定」，**满足后自动可用，没有任何按钮需要打开**。所以控制台上永远找不到一个叫「开通抠图」的地方。

控制台上能**看到**抠图的三个位置（都只是入口，不是开通开关）：

| 位置 | 路径 | 用途 |
|---|---|---|
| **智能工具箱** | 数据万象控制台左侧导航 → 智能工具箱 → AI 处理 → 通用抠图 | **在线传图直接看抠图结果**，验证最省事，见第 8 节 |
| 内容识别 | 数据万象控制台 → 存储桶管理 → 点桶名进桶 → 左侧「内容识别」 | 控制台默认开启，可建异步批量任务（本项目不用） |
| 图片处理样式 | 存储桶 → 图片处理 → 图片处理样式 | **本项目不需要，列表为空是正常的** |

> **关于「图片处理样式」为空**：本项目不预建样式，而是直接请求 `?ci-process=AIPicMatting` 这类处理参数。样式是「把一组处理参数存成别名」的便利功能，与本方案的调用方式无关，空着不影响抠图。
>
> **反向体检**：如果进「智能工具箱 → AI 处理」发现菜单里没有「通用抠图」（或只有「商品抠图」），说明桶所在地域不支持，或者万象服务/绑定没生效，回上面两条检查。

## 4. 取桶名与地域

1. 回到 <https://console.cloud.tencent.com/cos> → 「存储桶列表」。
2. **名称**列就是完整桶名，形如 `bagcollect-1250000000`。末尾那串数字是你的 APPID。
   本项目要求桶名**必须带 APPID 后缀**（代码里要从后缀解析账号 ID 来拼权限资源），所以不要只填 `bagcollect`。
3. **地域**列显示中文（如「广州」），按上表转成 `ap-guangzhou` 填进配置。
4. 不确定时，点桶名进详情页，「基本信息」里的访问域名是最可靠的判据：
   `bagcollect-1250000000.cos.ap-guangzhou.myqcloud.com` —— 域名中间那段就是地域代码。

## 5. 创建 CAM 子用户并拿到密钥对

> **密钥不在 COS 控制台生成。** 它属于**访问管理（CAM）**，挂在「用户」下面 —— 在 COS 页面里翻是永远找不到的。COS 控制台只管桶，不管密钥。

**不要用主账号密钥。** 主账号密钥一旦泄漏等于整个腾讯云账号失守。

直达链接：子用户列表 <https://console.cloud.tencent.com/cam/user>

1. 打开 <https://console.cloud.tencent.com/cam>（访问管理），用**主账号**登录。
2. 左侧「用户」→「用户列表」→「新建用户」→ 选「**自定义创建**」。
3. 访问方式**只勾「编程访问」**。本项目只用密钥调 API，不需要控制台登录权限，关掉能显著降低风险。
4. 走到第 3 步「设置用户权限」时停一下 —— 这是唯一需要动脑的一步，**列表里的预置策略一个都不要勾**，具体见下方专节。
5. 继续到「审阅信息和权限」，确认后点「完成」。
6. 在用户列表点进刚建的子用户 → 「API 密钥」页签 → 「新建密钥」。
7. 复制 **SecretId** 和 **SecretKey**：
   - SecretId 形如 `AKIDxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`；
   - SecretKey 是 32 位随机串，**只在这一步完整显示一次**，关掉就看不到了（只能删除重建）。
   - 复制时注意别带上空格或换行，这是最常见的「配置明明填了却说密钥无效」的原因。
   - 每个子用户最多创建 2 个密钥，够用，不用多建。

### 第 3 步「设置用户权限」怎么选 ← 最容易勾错的一步

这一页有上千条预置策略，**一条都不要勾**：

| 千万别勾 | 为什么 |
|---|---|
| `AdministratorAccess` | 全局权限，等于把这个子用户变成第二个主账号。它排在列表第一位，还标着「高风险」 |
| `QCloudResourceFullAccess` | 同样标注「高风险」的全局权限 |
| `ReadOnlyAccess` | 全局只读，本项目用不到 |
| 「常用策略」里的「自主管理 API 密钥」 | 会让子用户能自己创建、删除密钥，反而扩大风险面 |
| 「常用策略」里的「自主管理 MFA 设备」 | 只对控制台登录有意义，本项目只用编程访问 |

**正确做法：点这一页左上角的蓝色「新建自定义策略」按钮**，按第 6 节的 JSON 建一条只够本项目用的策略。腾讯云的交互是创建完成后自动回到本页、并把它勾上。

> **如果那个按钮把你带离了创建流程，或你不确定能不能回到本页**：改用官方推荐的顺序 —— **先建策略，再建用户**。先按第 6 节在 CAM 左侧「策略」里把策略建好，然后回到「用户 → 用户列表 → 新建用户」重新走一遍，到第 3 步在搜索框里搜策略名勾选即可。这样第 3 步只剩一个复选框要勾，不会遇到流程中断。
>
> 重新走一遍向导的代价很小：用户信息只有用户名和「编程访问」两项，基本不用重填。

## 6. 给子用户配权限策略

路径：CAM 左侧「策略」→「新建自定义策略」→ 选「**按策略语法创建**」→ 模板选「**空白模板**」→ 把下面的 JSON 粘进去。策略名建议用 `BagCollectAccess`，备注写「BagCollect 服务端读写 COS 与万象抠图」。

> 如果你在第 5 节向导里点过「新建自定义策略」，打开的就是这个创建页，内容确认无误后保存即可 —— 保存完会自动跳回向导并勾选。

**先替换三处占位符**：

| 占位符 | 换成 |
|---|---|
| `ap-guangzhou` | 你第 4 步拿到的地域，出现在两处 |
| `1250000000` | 你的 APPID |
| `bagcollect-1250000000` | 你的完整桶名 |

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "cos:GetObject",
        "cos:PutObject",
        "cos:HeadObject",
        "cos:DeleteObject"
      ],
      "resource": [
        "qcs::cos:ap-guangzhou:uid/1250000000:bagcollect-1250000000/*"
      ]
    },
    {
      "effect": "allow",
      "action": [
        "ci:CreateGoodsMattingJob",
        "ci:CreateS3AIPicMattingJob"
      ],
      "resource": [
        "qcs::ci:ap-guangzhou:uid/1250000000:bucket/bagcollect-1250000000/*"
      ]
    }
  ]
}
```

> **每个抠图能力对应各自的 action，互不通用。** 只授权 `ci:CreateGoodsMattingJob` 时，
> 把 `CI_MATTING_PROCESS` 改成 `AIPicMatting` 会直接 403：
>
> | 接口 | `ci` action | 单价 |
> |---|---|---|
> | `AIPicMatting`（通用抠图）← **本项目当前使用** | `ci:CreateS3AIPicMattingJob` ← 注意中间有 `S3` | 0.02 元/次 |
> | `GoodsMatting`（商品抠图） | `ci:CreateGoodsMattingJob` | 0.01 元/次 |
> | `AIPortraitMatting`（人像抠图） | `ci:CreateS3AIPicPortraitMattingJob` | 0.02 元/次 |
>
> **费用差异别忽略：通用抠图没有免费额度**，商品抠图有 1000 次一次性免费额度（2 个月有效）。
> 两个接口的选型理由与费用口径见 [腾讯云数据万象抠图实施方案](TENCENT_CI_MATTING.md) 第 1、2 节。
>
> 上面的 JSON 已同时包含商品抠图与通用抠图两条（切换与 A/B 对比都靠它，别删）；
> 如果确定只用一个，把不用的那条删掉即可。

这 6 个 action 对应项目里的每一处调用，一条都别删：

> 本项目当前实际在用的、已填好真实桶名与 APPID 的策略，见 `docs/cam-policy-cos-ci.json`，可直接整份粘贴。
> （上面这段是带占位符的模板，`1250000000` 和 `bagcollect` 都是示例值。）

| action | 谁在用 | 用途 |
|---|---|---|
| `cos:GetObject` | Worker / API | 读原图；万象抠图也走「下载时处理」，用的就是这个读权限 |
| `cos:PutObject` | Worker / API | 上传裁剪图、抠图结果、展示图和缩略图 |
| `cos:HeadObject` | API | 上传完成后校验对象存在与大小 |
| `cos:DeleteObject` | Worker | 清理失败任务的中间产物、删除收藏时清理对象 |
| `ci:CreateS3AIPicMattingJob` | Worker | 调用万象通用抠图（**当前使用的接口**）。**漏了这条，抠图必然失败** |
| `ci:CreateGoodsMattingJob` | Worker | 调用万象商品抠图（当前不用，保留用于切回或 A/B 对比）。不用可以删 |

**不需要 `sts:GetFederationToken`，写上去反而会被判为无效。** API 侧签发小程序直传临时密钥，是拿子账号自己的永久密钥去调 `GetFederationToken`，而这个接口**不做 CAM 鉴权**（官方原文：该接口只验签名不鉴权），所以子账号只要具备存储桶的操作权限就够了 —— 也就是上面那四条 `cos:*`。它不是一个 CAM action，所以策略分析器会报「无效的 action」。

**创建向导的第二步「关联用户/用户组/角色」就顺手把关联做掉**，不用事后再回来：

- 「将此权限授权给用户」→ 点「选择用户」→ 勾上你为 BagCollect 建的那个编程访问子用户 → 确定 → 「完成」。
- 这一步**可以跳过**（直接点「完成」）。跳过的话，之后去 CAM「用户 → 用户列表」→ 点进子用户 → 「权限」→「关联策略」→ 搜策略名勾选，效果一样。
- 如果「选择用户」列表里**找不到你的子用户**，说明第 5 节的子用户还没建。先把策略建完，再回第 5 节走一遍新建用户的向导，在第 3 步搜这条策略勾上。

> **策略名是自动生成的**（形如 `policygen-20260922172602`），而且**创建后不支持修改**。功能上没影响，但数量一多就分不清谁是谁。两个补救办法：一是在「描述」里写清用途（如「BagCollect：COS 读写 + 万象通用抠图」）；二是真想改名就重建一条 —— 走策略生成器重来一次只需几十秒。

创建完策略后，回到子用户详情页 → 「权限」→「关联策略」→ 选刚建的这条自定义策略。如果在第 5 节向导的最后一步就已经勾选过，说明已关联完成，跳过即可。

> **踩坑提示**：数据万象的 `ci:*` 资源描述格式与 COS 不同（是 `bucket/<桶名>/*`，不是 `<桶名>/*`），写错会表现为「策略已经关联了但仍然无权」。如果确认 action 没错却还是报权限错误，先把这一条的 `resource` 临时改成 `["*"]` 验证：改成 `*` 就通了，说明是资源描述写错了，改回来即可。

### 策略分析器报「无效的 action」怎么办

粘贴 JSON 后，编辑器下方的**策略分析器**可能会报 `错误：无效的 action`。它**一次只报一条**，修掉一条才显示下一条，所以要反复看几轮。

这个报错只有两个来源，按顺序排：

**1. 写成了 `sts:GetFederationToken` —— 这是本教程早期版本给错的一条建议，已修正。** 它不是一个 CAM action，删掉整条声明即可。官方 STS 接口文档写明该接口只验签名不鉴权，签发临时密钥本来就不需要授权，本项目也不需要这条。

**2. 抠图那条拼错了。** 两个 action 都是有效的（官方「下载时处理」的授权说明原文就是 `cos:GetObject` + 对应的 `ci:Create*MattingJob`），但容易被顺手写错：

| 错误写法 | 正确写法 | 说明 |
|---|---|---|
| `ci:CreateS3AIPicMattingJobs` | `ci:CreateS3AIPicMattingJob` | **单数，结尾没有 s**。数据万象其他 action 大多是复数（`ci:CreateMediaJobs`、`ci:CreateFileProcessJobs`、`ci:CreateDocProcessJobs`），顺手加个 `s` 就废了 |
| `ci:CreateAIPicMattingJob` | `ci:CreateS3AIPicMattingJob` | **通用抠图这条中间有 `S3`**，很容易顺手省略。少了它就是「无效的 action」 |
| `ci:CreateGoodsMattingJobs` | `ci:CreateGoodsMattingJob` | 商品抠图那条同理，是单数 |
| `name/cos:GetObject` | `cos:GetObject` | `name/` 前缀是旧版文档的写法，策略里不要写 |
| `cos:GetObjects` | `cos:GetObject` | 对象级动作没有复数形式 |

其他高频原因：

- 引号或逗号被打成了中文全角（`"` `，`）—— 从聊天窗口、文档里复制最容易中招。
- 复制时把 Markdown 代码块的 ` ```json ` 一起粘进去了。

> 分析器的「无效的 action」和「action 中无效的服务前缀」是两个不同的报错：前者是**名称**不认识，后者才是前缀不认识。看到的是前者，说明 `cos` / `ci` 前缀没问题，问题出在名称上。

**更省事的办法：别手写，走策略生成器。**

官方对「按策略生成器创建」的标注就是**优先推荐**，操作名由控制台列出来给你勾，不存在拼错的可能：

1. CAM 左侧「策略」→「新建自定义策略」→ 选「**按策略生成器创建**」。
2. 效果选「允许」，然后依次加两条声明（每加一条点一次「添加声明」）：

| 服务 | 操作 | 资源 |
|---|---|---|
| 对象存储 | 勾 `GetObject`、`PutObject`、`HeadObject`、`DeleteObject` | 第 4 步那个桶 |
| 数据万象 | 搜 `AIPicMatting`，勾 `CreateS3AIPicMattingJob`（想保留切换能力再加一条声明勾 `CreateGoodsMattingJob`） | 第 4 步那个桶 |

3. 起个名字（`BagCollectAccess`）保存。
4. 保存前切到「JSON」页签看一眼生成结果，那就是权威写法 —— 应该和上面那份 JSON 对得上。如果生成结果里出现了你手写没有的东西，以生成结果为准。

> 如果在数据万象的操作列表里搜不到 `AIPicMatting`，先回第 3 节确认数据万象已开通且桶已绑定（用第 9.1 节的方式验一下），再重新打开策略生成器。

## 7. 填进配置

本地开发填仓库根目录 `.env`（该文件不入库）：

```env
COS_SECRET_ID=AKIDxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
COS_SECRET_KEY=你的32位SecretKey
COS_BUCKET=bagcollect-1250000000
COS_REGION=ap-guangzhou
COS_PUBLIC_HOST=
```

生产环境填服务器上的 `infra/.env.deploy`（该文件禁止提交），变量名相同。

`COS_PUBLIC_HOST` 留空即可，它是可选的 CDN / 自定义访问域名；没有就让它空着。

**`STORAGE_DRIVER` 先不要动。** 下面第 9 步的验证脚本只读上面这 4 个变量，不需要 worker 完整启动。等验证通过、要跑完整图片链路时，再把 `STORAGE_DRIVER` 改成 `cos`——因为万象读不到本地磁盘文件，Worker 在 `local` 模式下会被配置校验直接拦下（这是预期行为）。

## 8. 要不要买控制台推荐的资源包

开通数据万象后，控制台会推三个 1.1 元的促销包。**它们都不是开通条件** —— 抠图默认按量后付费（0.01 元/次），一个包都不买也能立刻用。

| 推荐包 | 要不要买 | 原因 |
|---|---|---|
| 媒体处理 5 小时 | ❌ **不要** | 媒体处理是音视频转码（截帧、转码、智能封面）。BagCollect 只处理图片，没有视频链路 |
| 图片压缩 10 万次 | ❌ **不要** | 抵扣的是万象的 Guetzli 压缩与高级/极智压缩。项目里的压缩全部由 Worker 用 sharp 完成（标准 JPEG、2048 展示图、512 WebP 缩略图），**从不调用万象压缩接口** |
| 流量 50GB | ⚠️ **先别买**，见下 | 唯一可能用得上的一个，但取决于部署位置 |

> 「图片压缩」这一项还可以从控制台自证：图片处理页里的「图片高级压缩」「图片极智压缩」状态都是**已关闭**，本项目也不打算开，所以这个包永远不会被消耗。

### 流量包要不要买，只看一件事：Worker 和桶是不是同地域

抠图请求是「带 `ci-process` 参数访问 COS 域名」，按官方口径这类访问的流量计为**万象外网出流量**，中国大陆广州 0.6 元/GB。但官方同时写明：**相同地域内，腾讯云产品之间会自动使用内网访问，不产生流量费用**——默认域名 `xxx.cos.ap-guangzhou.myqcloud.com` 在同地域云产品内会被解析到内网 IP，不需要改用 `cos-internal` 域名。

所以判据很简单：

| Worker 部署在哪 | 抠图流量 | 流量包 |
|---|---|---|
| 腾讯云**广州**地域的 CVM / 轻量服务器（与桶同地域） | 走内网，**免费** | **不用买** |
| 本地开发机、其他云厂商、与桶不同地域的服务器 | 走公网，0.6 元/GB | 可以考虑买 |

50GB 按量是 30 元，1.1 元买到确实划算，但先看量级：抠图结果按 3MB 估，50GB ≈ 17000 张，而 17000 张的**抠图处理费本身就是 170 元**——流量费大约只占抠图总成本的 15%，而把 Worker 部署到与桶同地域能直接把这一项降到 0。

**结论：先不买。** 部署时让 Worker 和桶在同一个地域，这个成本项就不存在了。三个包都是「限购 1 个」的常态折扣，不是限时活动，真需要时随时能买。

> **别把它和 C 端流量搞混**：小程序用户拉展示图、缩略图产生的流量**不带万象处理参数**，属于 **COS 外网下行流量**，由 COS 收取，**不能用这个万象流量包抵扣**。C 端流量才是长期的大头——将来要买流量包，应该买 COS 的外网下行流量包，不是这一个。

## 9. 验证

验证分两步，**先用控制台确认服务通了，再用脚本确认代码链路通了**。不要跳第一步。

### 9.1 先在控制台确认（30 秒，最快，且不用配任何东西）

打开数据万象控制台 → 左侧导航「**智能工具箱**」→ 「AI 处理」→ 「**通用抠图**」，传一张纸袋图，看输出是否为透明背景。

- 能看到透明背景：说明**服务开通、桶绑定、地域支持**三件事全部就绪，可以去 9.2 了。
- 菜单里没有「通用抠图」，或提示无权/未开通：说明地域不支持或绑定没生效，回第 3 节。

### 9.2 再用脚本跑真实链路

拿一张真实的收藏品照片（纸袋、书、唱片之类），在仓库根目录跑：

```bash
pnpm ci:verify-matting -- /absolute/path/to/photo.jpg
```

脚本会按真实链路量级上传到 COS、调用万象抠图、校验尺寸与透明区域，把结果 PNG 写到 `data/ci-matting-verify/<时间戳>/`，结束后自动清理 COS 上的临时对象，并打印耗时、主体像素占比和费用估算（0.01 元/张）。

看到结果 PNG 是**透明背景 + 完整主体**，就说明桶、地域、万象绑定、密钥、策略五项全部正确。

> **本项目已于 2026-09-22 走完这一步**：`1/1` 通过，输入输出均为 `1280x1707`（1:1 返回），单张约 `1.3–1.7s`，费用 0.01 元（当时用的是商品抠图）。

> **注意：这一步通过只说明「配置对了」，不说明「效果可用」。** 同一天用同一张图跑 A/B 发现，商品抠图在生活化照片上几乎原样返回（主体占比 83.87%），换成通用抠图后才降到 36.72%。配置正确与效果达标是两件事，详见 `TENCENT_CI_MATTING.md` 7.2。
> 当时的配置：桶 `bagcollect-<APPID>` @ `ap-guangzhou`，策略见 `docs/cam-policy-cos-ci.json`。
> 结论与后续样本要求见 [数据万象抠图实施方案](TENCENT_CI_MATTING.md) 第 7 节。

**注意：链路跑通不等于效果达标。** 上面这次用的是生活化照片，不能作为效果判据；生产接口已于 2026-09-22 切换为 `AIPicMatting`，但仍需用**真实包袋商品图**跑满 10 张复核。

## 10. 报错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `AccessDenied` / 403 | 策略缺 action，或 resource 写错 | 对照第 6 节检查，注意 CI 那条的资源格式 |
| 浏览器探测 403，但上传/抠图仍 `AccessDenied` | 策略里的桶名与 `COS_BUCKET` 不一致（改过桶名却忘了改策略） | 见 10.2 坑一，两处 resource 都要同步改 |
| 提示密钥无效 / `SecretId is invalid` | SecretId 或 SecretKey 复制时带了空格、换行，或密钥被禁用 | 回子用户「API 密钥」页重新复制，必要时删除重建 |
| `NoSuchBucket` / `The specified bucket does not exist` | 桶名写错，或地域写成了桶实际所在地域之外的地方。**两者返回同一个错误**，所以都要核。APPID 数字段写颠倒也走这条 | 用下面的无密钥探测法先分清是哪一种 |
| `200` + XML 报未开通 / 无权限 | 数据万象没开通，或桶没绑定，或第 3 步的服务角色没授权 | 回数据万象控制台检查存储桶管理里的绑定状态 |
| 报错说图片不符合要求 / 抠图失败 | 图片超过 10MB，或分辨率超过 7680×4320，或格式不是 PNG/JPEG | 对照第 11 节限制 |
| 小程序上传 403 / `AccessDenied` | 子账号缺 `cos:PutObject`（要么签发临时密钥就被拒，要么密钥拿到后传不上去） | 确认那四条 `cos:*` 已关联到子用户 |
| 之前能用，某天突然不行 | 有人手动**解绑**了数据万象 | 万象解绑后无法恢复使用，需要重新绑定 |

> 万象在权限不足、服务未开通这类情况下**不会返回 4xx**，而是返回 `200` + XML 错误体。所以别只看状态码，小程序端和 Worker 日志里的错误信息会带上万象返回的 Code。

### 10.1 桶名/地域到底对不对：无密钥探测法

`NoSuchBucket` 是最容易卡住的一个，因为**桶名写错和地域写错返回的是同一个错误**，光看报文分不出来。用下面这个不需要密钥的探测可以立刻分清：

在浏览器里打开（把桶名和地域换成你的）：

```
https://<桶名>.cos.<地域>.myqcloud.com/
```

| 返回 | 含义 |
|---|---|
| `403` + `AccessDenied` | **桶存在、地域正确**（私有桶匿名访问被拒是正常的）。问题不在桶，去看权限 |
| `404` + `NoSuchBucket` | 桶名或地域不对，也可能桶根本没建成功 |
| `400` + `InvalidRequest`，消息里有 `Bucket format should be <bucketname>-<appid>` | 桶名忘了带 `-APPID` 后缀 |
| 域名解析失败 | 地域代码拼错了（如把 `ap-guangzhou` 写成 `ap-guanghzou`） |

要注意官方域名里**桶名后必须带 APPID 后缀**，所以 `https://bagcollect.cos.ap-guangzhou.myqcloud.com/` 这种写法一定会报 `InvalidRequest`，这不是桶不存在。

反过来说：只要探测返回 403，`COS_BUCKET` 和 `COS_REGION` 就一定是抄对的，可以放心往下查权限。

### 10.2 两个最容易搞混的组合：403 却能上传失败 / 浏览器和脚本结论不一致

实际配置时踩过的两个坑，都很隐蔽：

**坑一：探测 403（桶存在），但 `PutObject` 仍然 `AccessDenied`。**

这说明**桶是对的，但 CAM 策略里的桶名没跟着改**。COS 对「资源不在策略覆盖范围内」和「资源不存在于该账号」返回的都是 `AccessDenied`，报文完全一样，看不出区别。典型场景是先按错误的桶名建了策略，之后才发现桶名抄错、只改了 `.env` 却忘了改策略。

→ **凡是改过 `COS_BUCKET`，就必须同步改策略里的 resource。** 两处（COS 一条、CI 一条）都要改。

**坑二：浏览器访问返回 403，脚本探测返回 404。**

同一个域名不该有两种结论。出现这种情况，几乎一定是**两边的桶名不一样**——人在浏览器里手敲或用补全时，很容易在 APPID 那串数字上出错。

APPID 是 10 位数字（形如 `1250000000`），**数字段极易写颠倒**。而且它不会触发任何格式报错——`InvalidRequest` 只校验「有没有 `-` 和数字后缀」，不校验这个 APPID 是否属于你。写错的唯一症状就是 `404 NoSuchBucket`。

→ **对策：不要手敲 APPID。** 从控制台「存储桶列表 → 名称」列整串复制。已经写进策略里的话，改桶名时一定要连策略一起改。
→ 拿不准就用 `pnpm ci:list-buckets` 把真实桶名列出来（需临时授予 `cos:GetService`）。

## 11. 需要留意的服务限制

这些是官方限制，会直接影响图片处理能否成功：

| 限制项 | 数值 | 与本项目的关系 |
|---|---|---|
| 输入图片大小 | ≤ 10MB | 原图上限是 30MB，但送抠图的是重新编码后的裁剪图，通常 2~5MB，有余量；极端高细节图需要实测确认 |
| 输入分辨率 | 最小 32×32，最大 7680×4320 | 标准化后的图最长边 4096px，安全 |
| 输入格式 | PNG / JPEG / JPG | 裁剪图是 JPEG，安全 |
| 抠图并发 | 默认 5 QPS | 配置里 `CI_MATTING_MAX_CONCURRENCY=4`，在限额内 |
| 计费 | 通用抠图 0.02 元/次（商品抠图 0.01 元/次，**通用抠图无免费额度**） | 每次重试都重新计费，所以 `CI_MATTING_RETRY` 保持默认的 1，别调大 |
