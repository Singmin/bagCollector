# 纸袋 A/B 面

## 产品规则

- `FRONT` = A 面／正面，固定主图；`BACK` = B 面／反面，可选。列表、展架、分享继续取正面。
- 自上传收藏可添加、替换、裁剪、调色与抠图；两面均可替换，仅反面可单独移除。详情大图可左右切换两面。
- 官方袋子的图片仅管理员维护。用户认领后的图片引用官方库，不复制图片、不占用户图片空间；用户仍可修改自己的收藏信息。
- 官方更新成功后，下次刷新列表或重新打开详情读取新图片；没有实时推送。用户私人名称、分类、数量、日期、标签和备注不会随官方图片一起覆盖。
- 管理端两面分别上传和选择抠图设置。已发布袋子的正面必须先下架才能移除，反面可独立移除。
- 仍被认领收藏引用的官方袋子不能整条删除，可先下架；接口和数据库外键同时保护引用，避免用户收藏失去图片。认领事务会重新检查官方条目可用性，避免下架／删除并发时创建失效收藏。

## 数据与版本

`ImageAsset` 与 `OfficialBagImage` 增加 `side`，唯一键包含所属袋子、图片类型、面别和版本。

`CollectibleImageSide`、`OfficialBagImageSide` 分别以袋子 ID + 面别为主键：

| 字段 | 用途 |
| --- | --- |
| `sourceVersion` | 当前上传原图及标准图版本；0 表示该面已移除 |
| `processingVersion` | 单面任务单调递增的版本；移除也递增，使旧任务失效 |
| `publishedVersion` | 已完整生成并可展示的产物版本 |
| `publishedSourceVersion` | 已发布产物所依据的来源，用于审核复制，避免拿新来源配旧展示图 |
| `processingStatus` / `processingError` | 当前单面的进度和错误 |
| `crop` | 用户单面的裁剪与调色参数 |
| `mattedSourceVersion` | 用户已成功抠图的来源版本 |
| `matting` | 官方单面下一次上传的抠图设置 |

展示图、缩略图、透明图严格取同一已发布版本。标准图用于当前来源的编辑。新图或编辑失败时，保留旧展示图；只在完整产物生成后切换已发布版本。袋子级处理字段是 A 面兼容投影，B 面不改变它。

新对象路径包含 `front` / `back`，历史对象路径原样保留。队列载荷包含面别、来源版本、任务版本和参数快照。写资产、发布与删除通过所属袋子的锁和版本条件协调；删除后不重建图片记录，过期任务写出的对象交给清理。Redis job ID 使用 SQL 幂等键的 SHA-256，避免 BullMQ 禁止冒号的限制。

## 接口

- `POST /uploads/policy`：增加可选 `side`，默认 `FRONT`；支持给已有自上传收藏添加或替换图片。
- `POST /uploads/complete`：通过资产 ID 确定面别，校验上传仍属于当前来源。
- `POST /collectibles/:id/crop`、`POST /collectibles/:id/matte`：增加可选 `side`、`sourceVersion`；缺省面别兼容旧客户端，提供来源版本时拒绝过期编辑。
- `DELETE /collectibles/:id/images/BACK`：仅移除自上传收藏的反面及其资产，更新用户空间核算。
- `POST /admin/official-bags/:id/image?side=FRONT|BACK&matting=true|false`、`DELETE /admin/official-bags/:id/image?side=FRONT|BACK`：按面上传／移除。
- 官方新建／更新表单支持 `matting` 和 `backMatting`，分别保存正反面下次上传的抠图设置；修改设置不改写已经入队的参数快照。发布时在同一袋子锁内校验正面已有完整已发布产物，避免与移除图片并发。
- 收藏与官方详情新增 `sides`、`imageRevision`；收藏详情及摘要另有 `imageEditable`、`sourceOfficialBagId`。旧图片 URL 字段始终对应正面。
- 官方认领收藏的图片写操作返回 403；拥有者仍可修改收藏信息。面别无效返回 400，处理中重复提交或过期来源返回 409。

## 编辑与失败处理

完善信息页选择编辑面。进入拍照页传收藏 ID 和面别，添加反面不新建收藏；此模式不提供扫描识别。

裁剪页保留正反面 tab，各面分别保存构图、调色与抠图选择。切换不提交；应用提交所有修改过的面；取消不发送调整。无图片的反面 tab 禁用。各面结果独立，处理页保留失败面及草稿，重试跳过已经成功的面。

表单草稿按收藏 ID 存储，图片处理返回时仅刷新图片状态。保存完成清除草稿。直接确定添加时，对尚未裁剪的面补全幅裁剪；反面失败可重新编辑／替换或移除后保存。

抠图开关默认关闭。用户每日配额计入成功和进行中的主动抠图任务；同一来源成功后不重复主动提交。已抠图来源重新裁剪会重新调用万象，以保持构图和透明图一致。**用户配额次数不等于实际云服务调用次数**，重新裁剪和失败后的人工重试仍可能产生云服务成本。

## 审核与识别边界

审核后台可预览 A/B 面；纳入官方库时复制正面和已发布反面的完整产物，使用各面已发布来源版本。原上传收藏仍由用户编辑，不因纳入官方而改成官方认领。

**本期 B 面仅用于展示，不参与扫码识别。** 主参考向量、旧视觉向量及查询图明确选 A 面；既有参考图库继续使用。

## 迁移与发布

迁移 `20261012000000_image_sides` 在单一 PostgreSQL 事务中执行：存量归正面；按最新完整展示图／缩略图版本回填；有效认领关系补齐官方引用；历史认领复制图归档并释放用户配额，保留对象路径，后续删除收藏时不重复返还配额；历史对象路径不变。

首次升级沿用 CI → `load-and-deploy.sh` → `deploy.sh`。部署脚本发现旧库尚无分面表时，暂停旧 API 写入，让旧 worker 排空图片队列，再停止旧 worker、执行迁移并启动新应用。排空超过 120 秒中止，迁移前失败可恢复旧镜像。

**本次改变资产唯一约束，旧应用不具备双面写入能力。** 分面迁移成功后若新应用启动失败，部署脚本停止图片应用并保留新 schema，必须修复后向前发布，不能自动恢复旧图片写入应用。迁移之后的历史单面版本同样不得直接回滚到线上。
