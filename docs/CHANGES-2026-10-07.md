## 二、认领官方袋子改为「引用官方图」（`7432835`）

「标记已有」认领官方袋子时，此前会把官方图片**复制**到用户名下（占存储、走后台队列）。现改为**直接引用官方图**：不复制图片、不占用户存储、落库即 `READY`。

### 1. 数据模型

- `Collectible` 新增 `sourceOfficialBagId`（引用被认领的官方袋子）
- `OfficialBag` 新增反向关系 `claimedCollectibles`（`@relation("CollectibleSourceOfficialBag")`）

### 2. 认领逻辑（`official-bags.service.ts`）

- 不再往 `official-claim` 队列投递图片复制任务，移除 `QueueService` 依赖
- `processingStatus` 从 `NORMALIZING`（等复制完成）改为落库即 `READY`，收藏列表立即可见
- 图片 URL 直接读官方库

### 3. worker 清理

- `apps/worker/src/processor.ts` 移除 `official-claim` 复制处理逻辑

### 4. 生产迁移脚本（`scripts/migrate-claims-to-reference.mjs`）

把历史认领收藏从「复制模式」转「引用模式」：

- 只处理 `sourceOfficialBagId IS NULL` 的记录（幂等可重跑）
- 只清理「纯复制」资产（`version <= 1` 且无 `CROPPED`），编辑过的跳过并告警
- 先回填引用 → 再删资产 + 扣配额（同事务）→ 最后删 COS
- 删除前把 `objectKey` 清单落盘 `/tmp/claim-migration-manifest.json` 供对账
- 默认 `dry-run`（只统计 + 写清单），加 `--execute` 才真正执行

配套 3 个只读 SQL（纯 `SELECT`，本次提交入库）：

| 脚本 | 用途 |
|---|---|
| `scripts/analyze-claims.sql` | 转换前分析：总量、按状态分布、可安全转换 vs 需保留、可释放对象清单 |
| `scripts/query-failed-claims.sql` | 非 `READY` 的认领收藏详情 |
| `scripts/verify-claims-migration.sql` | 转换后验证：三项应都等于 0 |

## 三、收藏配额只统计可见收藏（`dc4c8bd`）+ 上限放开（未提交 → 本次提交）

> 本节后半段「上限 500 → 9999」为工作区改动，随本次提交入库。

新增 `apps/api/src/common/quota.ts`，定义 `QUOTA_COUNTED_STATUSES`：

```
READY + NORMALIZING / CROPPING / MATTING（处理中，马上变 READY）
```

`create` 与 `claim` 的配额统计从 `_count.collectibles`（全量）改为只统计上述状态，**排除**三类「列表里不可见、却悄悄吃掉配额」的记录：

- `UPLOADING` —— 只建了记录、图片还没传
- `AWAITING_CROP` —— 图已传、但停在裁剪页没点「确定添加」
- `FAILED` —— 处理失败

修复前这些「隐身草稿」会把配额从暗处顶满，挡住用户继续拍照。

### 单用户收藏上限放开

- `MAX_COLLECTIBLES_PER_USER` 由 `500` 上调为 `9999`（同步 `.env.example` / `apps/api/src/common/env.ts` / `infra/.env.deploy.example`）
- 配合「认领官方袋改引用模式、不再复制图片占存储」，用户收藏上限不再被官方袋挤占

## 四、小程序 UI 打磨（本次提交）

### 1. 我的收藏页（`pages/library/index.vue`）

- **展架横向滚动卡顿修复**：`onShelfScroll` 不再把 `scrollLeft` 每帧回写进响应式 `shelfScrollLeft`（`:scroll-left` 绑定），避免滚动事件每帧 `setData` 与手指抢滚动条导致的「一卡一卡」。位置记在非响应式 `shelfMetrics.left`，边缘态仅在跨过边界时更新，减少箭头重渲染。
- **内容不满一屏自动补拉**：新增 `fillViewportIfNeeded()`，在 `load` / `loadMore` 后测量内容高度，若仍低于视口且还有下一页则自动继续加载，解决「首屏只有 30 条 + 单展架时无滚动条、后续分页拉不出来」的问题。
- **数量角标调整**（用户 2026-10-06 要求）：`qty-badge` 贴紧卡片右上角 + 缩小字号，右上圆角由模板按 `gridRadius` 内联注入（跟随捏合缩放）；展架视图角标上移到袋顶。
- **大图预览浮层**：新增 `.preview-layer` / `.preview-image`，点详情图区打开，点遮罩或图片任意处关闭；图片比整屏小一档，留出四周空间看轮廓与投影。

### 2. 发现页（`pages/showcase/index.vue`）

- **虚拟列表越界修复**：`updateVisibleRange` 的 `start` 收敛到 `[0, max(0, len-1)]`，避免刷新后 `scroll-view` 以旧 `scrollLeft` 派发 scroll、`start > end` 导致整排卡片消失。
- **翻面防误触**：新增 `FLIP_SETTLE_MS = 800` + `flipSettling()`，翻面动画落定前忽略主卡上的心愿 / 标记点击与重复翻面，避免双击翻面第二下正好压在背面按钮上误触发。
- **备注区可滚动**：`back-note` 从「限两行裁掉」改为固定高度（约两行）的纵向滚动区，长备注（最长 2000 字）可在框内上下滑。
- **滚动条隐藏兜底**：多处 `scroll-view` 补 `enhanced` + `:show-scrollbar="false"`，并加 `::-webkit-scrollbar` 伪元素（含全局样式）兜底——`enhanced` 在部分真机 / 基础库上不生效。

### 3. 共享编辑样式（`styles/edit-form.css`）

- 数量步进器 `ef-qty`：`− N ＋` 圆钮改为左对齐、不拉满整行（`gap: 30rpx`）。
- 可见性分段 `ef-vis__opt`：从 `flex: 1` 拉满改为 `flex: 0 0 auto` + 固定内边距的胶囊，选中态品牌红。

## 六、部署注意事项

- **改了 Prisma schema，务必先跑迁移**：本次新增 `Visibility` 枚举、`quantity` / `visibility`、`sourceOfficialBagId` 字段，部署时执行 `pnpm db:deploy`；未重新生成 Prisma Client 前，api / worker 构建会报 `Property does not exist on PrismaClient`。
- **认领引用模式转换需在 api 容器内执行**：`node scripts/migrate-claims-to-reference.mjs`（默认 dry-run），确认无误后再加 `--execute`。执行前建议先跑 `analyze-claims.sql` 看分布，执行后用 `verify-claims-migration.sql` 验证三项为 0。
