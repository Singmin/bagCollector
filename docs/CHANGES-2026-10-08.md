## 二、API：品牌分类接口与认领 / 心愿互斥

### 1. `GET /official-bags/brands`（`official-bags.controller.ts` / `official-bags.service.ts`）

- 只返回「旗下有可见袋子」的品牌，件数口径与列表一致（`PUBLISHED` + `READY`），按 `sortOrder desc, name asc`
- ⚠ 路由**必须声明在 `@Get(':id')` 之前**，否则 `/official-bags/brands` 会被 `:id` 吞掉

### 2. 心愿与「已拥有」互斥

- `addWishlist`（`feed.service.ts`）：已认领（`officialClaim` 存在）的袋子不再允许进心愿袋，返回 `409 CONFLICT`「这只袋子已在收藏架」。前端按钮会置灰，这里是多端 / 旧客户端绕过 UI 时的兜底
- 认领事务（`official-bags.service.ts`）：创建 `officialClaim` 的同时删除同名 `wishlistItem`，与前端「标记成功自动移出心愿袋」同一规则，避免落库出「既已拥有又想要」的矛盾状态

## 三、本地联调：固定登录 code 与 mock 数据

- `apps/miniapp/src/config.ts` + `services/http.ts`：新增 `VITE_WECHAT_MOCK_CODE`（仅 `--mode localbuild` 注入）。后端 `WECHAT_AUTH_MOCK=true` 时 `openid = mock_ + sha256(code)`，而 `uni.login` 每次生成随机 code → 每次启动都新建一个空账号、看不到 mock 数据；固定 code 才能稳定命中同一个用户。生产构建读不到该变量，仍走真实 `uni.login()`
- `scripts/seed-local-mock.mjs` + `pnpm seed:local:mock`：一键把品牌分类 / 官方纸袋 / 展架 / 收藏 / 心愿 / 标签灌进本地空库。worker 在本地跑不起来（抠图链路强制 COS），故图片处理完成态由脚本直接落库 + 落盘模拟（`STORAGE_DRIVER=local`，API 走 `/api/assets/file?token=...` 读回，小程序能直接显示）
  - 所有 id 带 `mock` 前缀，`--reset` 精确清理，不碰真实数据（真实 cuid 以 `c` 开头）
  - `--openid mock_xxx` 可挂到指定用户，默认挂本地联调固定 code 的用户

## 四、首页挂袋区偶发空白修复（`showcase/index.vue`）

现象：滑过挂袋区若干张后，切 tab 回来 / 下拉刷新 / 从图鉴页返回，**标题「精选上新」「今日上新 · N 件」与亚克力挂杆都在，整排卡片空白**，横向滑一下才恢复。

### 根因

挂袋区是虚拟列表，滚动内容总宽由左右占位（`leadSpace` / `tailSpace`）撑起，**刷新前后总宽完全守恒**。

1. `load()`（每次 `onShow`、下拉刷新都跑）成功后无条件 `updateVisibleRange(0)`，把渲染窗口硬重置到列表开头
2. 但总宽守恒意味着 `scroll-view` 的 `scrollLeft` 不会随数据刷新复位，仍停在用户滑到的位置
3. 于是窗口只渲染最左端那批卡片，视口却落在右侧的 `tailSpace` 空白占位上 → 整排消失

滑过约 7 张卡（≈980px）以上必现，滑得少就不出现，所以表现为「偶发」。10-07 那次 clamp 修的是 `start > end`「数组被切空」这条路径，与本条无关。

### 修复

- 新增 `syncRailWindow()`：刷新后按**最后一次真实滚动位置**重建窗口（首屏该位置为 0，行为不变），替代原来的固定 0
- 追加一次 `scrollOffset` 校准：兜住「滚动事件缺最后一帧（页面隐藏期间的惯性）/ 内容被静默 clamp」的情况，差值小于一张卡则跳过
- `railLastLeft` 从摆动的 80ms 节流里拆出来、每帧更新（速度基准另用新增的 `tiltLastLeft`）：否则快速滑到底后立刻刷新，记下的还是几十毫秒前的旧值
