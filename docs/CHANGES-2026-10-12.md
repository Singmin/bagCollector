## 一、纸袋 A/B 面（image-sides）

> 详细设计见 [docs/BAG_SIDES.md](BAG_SIDES.md)，此处仅按层列出改动落点。

### 1. 数据模型（`prisma/schema.prisma` + 迁移）

- `ImageAsset` / `OfficialBagImage` 增加 `side`（`FRONT` / `BACK`），唯一键纳入所属袋子、图片类型、面别和版本。
- 新增 `CollectibleImageSide` / `OfficialBagImageSide` 两张「袋子 ID + 面别」主键的分面状态表，承载来源版本、处理版本、已发布版本、进度、裁剪参数、抠图状态等。
- 迁移 `20261012000000_image_sides`：单一事务内把存量归正面、回填版本、修复官方引用、归档历史认领复制图，历史对象路径不变。

### 2. API / worker

- 新增 `apps/api/src/common/image-sides.ts`：`imageData`（按发布指针读资产并拼出 `sides` + `imageRevision`）、`selectSideAssets`、`lockImageOwner`（跨面串行化配额）、`failImageSubmission` 等共享逻辑。
- `collectibles` / `uploads` / `official-bags` / `submissions-admin` 各 service 从单面字段重构为分面读取与写入；`crop` / `matte` / 上传 / 移除均支持 `side` 与 `sourceVersion`，缺省面别兼容旧客户端。
- 官方袋子两面分别上传与抠图设置；已发布正面须先下架才能移除，反面可独立移除；仍被认领引用的官方袋子不能整条删除。
- 认领事务增加 `FOR UPDATE` 行锁并复查官方条目可用性，避免下架／删除并发时创建失效收藏。
- worker `processor` / `official-processor` / `asset-record` / `bag-embeddings` 同步改为双面处理；队列载荷携带面别、来源版本、任务版本与参数快照，Redis job ID 使用 SQL 幂等键的 SHA-256 规避 BullMQ 冒号限制。
- 部署脚本 `infra/deploy.sh`：发现旧库尚无分面表时，先暂停旧 API 写入、排空旧 worker 图片队列，再迁移并启动新应用；分面迁移成功后不可回滚旧镜像（旧应用不具备双面写入能力）。

### 3. miniapp

### 4. admin（`apps/admin/src/App.tsx`）

## 二、小程序底栏组件化重构（tab-bar）

底栏从「原生 `custom-tab-bar` 组件 + App 实例总线」重构为「Vue 响应式状态 + `BagTabBar.vue` 组件」，去掉原生组件与页面之间的一条总线通信。

### 1. 原机制及其问题

`custom-tab-bar/index.js` 是原生小程序组件（不是 vue 文件），与 `services/tab-bar.ts` 靠挂在 `App` 实例上的一条总线（`__bagTabBarBus`，结构 `{ sinks, state }`）通信：页面侧推状态、组件侧订阅回放。

原机制有两个已知坑：

- 底栏组件会因输入框聚焦（键盘弹出、页面重排）被重新 `attached`，`data` 复位成默认值、隐藏态当场丢失，表现是「编辑半窗里点一下输入框，底栏又冒出来」。
- 底栏是框架层、渲染在页面内容之上，页面里的遮罩压不住它，只能靠总线「整条收起」。

### 2. 重构后

- `services/tab-bar.ts`：从总线机制改为 `reactive` + `readonly`，导出只读的 `tabBarState`（`{ selected, hidden }`）与 `syncTabBar(selected, hidden)` / `setTabBarHidden(hidden)`；`syncTabBar` 现在同时同步选中与隐藏两个状态。
- 新增 `components/BagTabBar.vue`：直接消费 `tabBarState` 渲染可见底栏（发现 / 添加 / 我的），保留原底栏的几何、配色与安全区间距。
- 两个 tab 页（`pages/showcase` / `pages/library`）直接 `<BagTabBar />` 渲染，不再依赖原生组件与总线。
- `custom-tab-bar/index.js` 缩减为 `Component({})` 占位、`index.wxml` 清为 `<view />`、`index.wxss` 清空 —— 保留 custom-tab 注册仅用于 `uni.switchTab` 路由，可见样式统一在 `BagTabBar.vue` 维护。

## 三、认领与识别微调

### 1. 再次认领同款叠加数量（`official-bags.service.ts` + `add/index.vue`）

- `POST /official-bags/:id/claim` 新增 `increment`：默认（标记已有）重复认领仍返回 409；扫描匹配再次认领已拥有同款时传 `increment=true`，不再新建收藏，而是把该收藏 `quantity` 加 1。
- 认领返回 `OfficialClaimResult` 增加 `quantity`（叠加后的同款数量）与 `alreadyOwned`（本次是否为再次认领）。
- 小程序 `add` 页：扫描匹配到已拥有同款时走增量路径，提示「这是你的第 N 个「袋子名」」。

### 2. 官方图鉴详情点开重新拉取（`explore/index.vue`）

- `openBag` 改为点开时用 `dataService.officialBag(id)` 重新拉取官方详情，并回写列表项，配合 A/B 面「官方更新后重新打开详情读取新图片、无实时推送」的规则；用 `detailRequest` 自增序号处理连续点击的竞态。

### 3. 「我的收藏」编辑图片入口 + 大图预览组件化（`library/index.vue`）

- 编辑半窗新增「编辑图片」按钮（仅 `imageEditable !== false` 且非心愿详情显示，官方认领收藏隐藏），跳转到完善信息页的编辑模式。
- 大图预览浮层从自建 `.preview-layer` 换成 `BagImagePreview` 组件，支持 A/B 面切换。

### 4. 发现页搜索图标缩小（`showcase/index.vue`）

- 官方图鉴入口图标按用户要求「搜索小一点点」微调：白框按胶囊高 0.88 缩放并垂直居中，放大镜图标再按 0.55 缩小。

## 四、验证与部署注意事项

- 改了 Prisma schema，部署务必先执行迁移（`pnpm db:deploy`）；未重新生成 Prisma Client 前 api / worker 构建会报字段不存在。
- 分面迁移成功后，历史单面版本不得直接回滚线上（旧应用不具备双面写入能力）。
- 新增集成测试已接入 CI：`test-image-sides-integration.mjs` 覆盖双面上传裁剪、失败保留旧图、移除后旧任务、官方更新同步与私人信息保留；`test-image-sides-migration.py` 验证存量回填与认领修复。
