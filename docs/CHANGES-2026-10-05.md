## 一、核心功能：用户投稿审核后台

用户上传的袋子（`Collectible`）从「纯个人收藏」升级为「可被后台审核、纳入官方精选」的投稿对象。后台能浏览、筛选、审核每一条用户投稿，决定「纳入官方」或「驳回」，并管理用户与审计记录。

### 1. 数据模型（`prisma/schema.prisma` + 迁移）

- 新增枚举 `SubmissionStatus`：`PENDING` / `APPROVED` / `REJECTED`
- `Collectible` 新增审核字段：
  - `submissionStatus`（默认 `PENDING`）、`reviewNote`（审核意见）、`reviewedById` / `reviewedAt`（审核人与时间）
  - `promotedBagId`（**唯一**，回链「纳入后生成的官方袋子」）
- `Admin` 新增反向关系 `reviewedSubmissions`；`OfficialBag` 新增 `sourceCollectible`（记录由哪个用户袋子纳入）
- 新增索引 `@@index([submissionStatus, addedAt])`，支撑按状态 + 时间排序的审核队列
- 迁移：`apps/api/prisma/migrations/20261005010000_submissions/migration.sql`（枚举 + 5 列 + 2 索引 + 2 外键，完整覆盖 schema 改动）

### 2. 审核接口（新增 `submissions` 模块，挂 `AdminGuard`）

| 端点 | 职责 |
|---|---|
| `GET /admin/submissions` | 列表，支持 `status` / `search` / `from` / `to` / `cursor` / `limit` |
| `POST /admin/submissions/:id/promote` | 纳入官方袋子（可覆盖名称 / 品牌 / 备注 / 标签） |
| `POST /admin/submissions/:id/reject` | 驳回，可附审核意见 |
| `POST /admin/submissions/:id/reopen` | 重新打开已审投稿 |

### 3. 用户管理接口（新增 `users` 模块，挂 `AdminGuard`）

| 端点 | 职责 |
|---|---|
| `GET /admin/users` | 用户列表（`status` / `search` / `cursor` / `limit`） |
| `GET /admin/users/:id` | 用户详情（配额 + 最近收藏） |
| `POST /admin/users/:id/suspend` | 封禁 |
| `POST /admin/users/:id/activate` | 解封 |
| `PATCH /admin/users/:id/quota` | 调整配额（存储 / 收藏数 / 每日抠图次数） |

### 4. 审计日志（`admin` 模块扩展）

- 新增 `GET /admin/audit-logs`，按 `action` / 日期区间过滤，游标分页
- 服务端新增 `parseDayBoundary` 把 `YYYY-MM-DD` 解析为本地时区当天起止时刻

### 5. COS 服务（`assets/cos.service.ts`）

- 新增 `getObject(key)`：读取对象完整字节，本地存储与 COS 驱动行为一致（「纳入官方」时把用户图片复制到官方库用）
- `publicUrl` 在本地存储模式下（`COS_BUCKET` 为空）**不再回退 COS 直链**，避免触发 cos SDK「missing param Bucket」

### 6. 契约（`packages/contracts/src/index.ts`）

- 新增枚举：`submissionStatuses`、`userStatuses`
- 新增校验 schema：`promoteSubmissionSchema`、`rejectSubmissionSchema`、`updateUserQuotaSchema`
- 新增 DTO：`SubmissionDto` / `SubmissionPageDto` / `AdminUserSummaryDto` / `AdminUserPageDto` / `AdminUserDetailDto` / `AuditLogDto` / `AuditLogPageDto`
- 处理状态补入 `CROPPING`（裁剪中）

## 三、小程序修复（`apps/miniapp`）

### 1. 全部收藏页（`pages/library/index.vue`）—— 宫格无法下滑

宫格视图容器上 `@touchmove.stop` 编译为 `catchtouchmove`，把单指滑动的 `touchmove` 拦截在容器内、不再冒泡给外层 `scroll-view`，导致宫格模式下页面滑不下去（展架视图正常，因为它没绑 `touchmove.stop`）。

- 修复：去掉两处（「我的」宫格与「心愿袋」宫格）`@touchmove.stop` 的 `.stop`，恢复单指竖向滚动
- 双指捏合缩放（列数 4~8）**保留**，不受影响
- 同步纠正宫格画廊注释：原注释写「不可捏合缩放」已过时，改为「固定 4 列起步、双指捏合 4~8 列」

### 2. 裁剪页（`package-editor/pages/crop/index.vue`）—— 图片对不上裁剪框 / 每次进入尺寸不一致

- **取景框与图片层同源居中**：`left/top:50%` + 负 `margin`，不再用 px 硬定位到「测量的舞台中心」；即便测量短暂偏差，两者中心仍重合，只影响整体缩放、不再错位
- **舞台尺寸连续两次读数一致才采用**：首次非零读数常是布局未定的过渡值，直接采用会让每次进入页面拿到的舞台尺寸不一致；改为读到稳定值再回
- **`crop-stage` 用 `absolute` 铺满父容器**：`height:100%` 依赖父级 flex 高度被视为「确定高度」，部分 WebView 解析不稳定；absolute 铺满规避

## 四、「拥有」官方袋子归类改进（`official-bags`）

「标记已有」认领官方袋子时，此前一律进默认「未分类」展架。现改为**按品牌归类**：

- 用户显式传了 `shelfId` → 用用户的
- 否则按官方袋子的品牌名找同名展架，找不到就新建
- 没有品牌才落到默认「未分类」

## 六、部署注意事项

- **改了 Prisma schema，务必先跑迁移**：CI / 生产用 `migrate deploy` 只应用已存在的迁移文件。本次迁移已随分支提交（`20261005010000_submissions`），部署时需执行 `pnpm db:deploy`。
- **合并后本地构建需重新生成 Prisma Client**：新增字段 / 关系后，未执行 `pnpm db:generate` 前，api / worker 构建会报 `Property does not exist on PrismaClient`，这不是代码问题。
