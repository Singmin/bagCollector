## 一、后端：图像处理流水线

### 1. 端点语义拆分（成本闸门）

原先「裁剪 + 抠图」混在一个端点里，用户只想裁剪时也可能触发万象抠图计费。现拆成两个：

| 端点 | 职责 | 是否调用万象 |
|---|---|---|
| `POST /collectibles/:id/crop` | 只裁剪（旋转 / 缩放 / 调色由 sharp 落盘） | 否 |
| `POST /collectibles/:id/matte` | 只抠图，沿用已保存的裁剪参数 | 是 |

- `collectibles.controller.ts` 新增 `@Post(':id/matte')`，并加注释说明两者不得再合并回一个端点
- `contracts` 新增 `matteSchema`，与 `cropSchema` 分离

### 2. 抠图互斥：`assertNotMatted()`

已抠图的收藏再次调用 `/matte` 返回 **409**，避免重复扣费。

### 3. 抠图之后仍可裁剪（rematte）

原先已抠图的图不允许再裁剪（否则新展示图与旧透明图构图失配）。改为：

- `/crop` **不再拦截**已抠图的图
- 通过 `hasCutout()` 判断，给任务置 `rematte` 标志
- worker 在 `rematte` 时走「裁剪 + 重新抠图」流水线，保证透明图与新展示图对齐
- **不计每日配额**：同一张图只算一次万象扣费（配额只在 `/matte` 入口计）

### 4. 每日配额只计成功

`dailyMattingQuota` 原先按「建了 MATTING 任务」计数，万象超时/报错也会吞掉配额，用户重试时撞上"今日次数用完"。改为**仅在成功落 CUTOUT 资产时** +1。

### 5. worker 流水线

- 新增 `writeRenditions()`、`cropToAsset()`、`cropImage()`
- `cropToAsset()` 取 `STANDARD where version <= data.version orderBy desc`，重裁/重抠不会命中旧版本图
- 调色参数（brightness / contrast / saturation）由 sharp 落盘（此前只在前端 canvas 预览）
- 幂等键 `crop:{id}:v{n}` / `matting:{id}:v{n}` 防重入

### 6. 数据模型与契约

- `prisma/schema.prisma` 调整
- 新增迁移 `apps/api/prisma/migrations/20260930010000_split_crop_and_matting/`
- `packages/contracts/src/index.ts` 同步新端点与字段类型
- `scripts/test-local-image-flow.mjs` 补充本地流程验证

## 二、小程序：图片编辑器 UI

### 1. 裁剪旋转页（`package-editor/pages/crop/index.vue`）

改造前的问题：控件平铺无分组、灰度色值三套混用、字号硬编码、画布孤立深底、底部按钮被挤出首屏。

| 项 | 改造前 | 改造后 |
|---|---|---|
| 画布 | 深底 `#141414`（观感重） | 纸感圆角卡 `#fffdf8` + 细边框 + 柔影，canvas 圆角 30rpx |
| 控件 | 平铺胶囊 + 混排行 | 主流修图 App 式「图标在上 · 文字在下」工具行 |
| 布局 | 比例、旋转分两行 | 比例（3:4/2:3/原图）与旋转（旋转 90°/重置）**同排一行、等宽均分** |
| 底部 | 87rpx 全宽胶囊「取消/应用裁剪」 | 88rpx 圆形轻量钮：✕ 取消 / ✓ 应用 |
| 调色 | 裁剪模式无入口，但每次都提交默认值 | 三个调色滑杆常驻 |
| 模式 | 存在独立的「仅调色」模式 | **删除**，与裁剪旋转完全复用同一页面 |

细节：
- 选中项文字变品牌红 `#C50405`
- 字号全部走 `--wc-font-*` token，灰度收敛为 `#141414 / #77736d / #a8a49d / #b3afa8`
- 滑杆去掉原生 `show-value` 气泡，改为「标签 / 滑杆 / 数值」三列
- `mode=color` 分支及其附属的 `mode`、`colorMode`、`savedCrop`、`Collectible` 类型导入一并清理

### 2. 完善信息页（`package-editor/pages/metadata/index.vue`）

- 三个入口**并排一行等宽**：裁剪旋转 / 高级调色 / 自动抠图（原为整行纵向堆叠）
- 三个图标统一为同一套线性描边规格（见「图标资源」）
- 自动抠图按钮**常驻**，已抠图时置「已抠图」完成态并禁用（原为直接隐藏，导致按钮数量变化、宽度跳动）
- 完成态样式写在 `[disabled]` 之后覆盖其 `opacity`，避免微信内置 `wx-button[disabled]` 把胶囊刷成"不可用"观感
- 按钮行与下方表单间距 6rpx → 32rpx
- 文案统一四字：裁剪旋转 / 高级调色 / 自动抠图

### 3. 陈列页（`pages/showcase/index.vue`）

- **大卡片背面支持卡内滚动**：内容超出时上下滑动，不显示滚动条
  - 用 `scroll-view` + `enhanced` + `:show-scrollbar="false"`
  - `enhanced` 必须开：`show-scrollbar` 是增强特性属性，只在 `enhanced` 为 true 时生效（项目内详情页 `detail-scroll` 踩过同样的坑）
  - 不加 `@tap.stop`，保证点击背面仍能翻回正面
  - `.back-inner` 从 `height:100% + overflow:hidden` 改为 `min-height:100%`（原写法会把超高内容直接裁掉且滚不动）
- **靶心图标随状态切换**：`target.svg`（黑）→ `target-marked.svg`（品牌红）
- 背面「标记已有」按钮同步状态：未标记＝黑底白靶心「标记已有」，已标记＝描边红靶心「已拥有」
- `markedMap` 从 `Map` 改为普通对象 `Record<string,string>`：小程序端对象属性的响应式更可靠

### 4. 全部收藏页（`pages/library/index.vue`）

**缺陷修复**：详情卡右上角靶心的「图标状态」与「点击行为」用了两套判据——
- 图标 `isOwnedDetail`：非心愿条目（即「我的」收藏）恒为「已拥有」，显示红环
- 点击 `markFromDetail`：只认 `justMarkedMap`（仅记录本次会话刚标记的心愿条目）

结果是「我的」收藏条目明明显示红环「已拥有」，点下去却拉起「标记已有」半窗，再走一遍会**创建重复收藏**。

修复后点击语义与图标严格一致：
- 心愿条目·本次刚标记 → 删除标记时创建的那条收藏（撤回，详情卡不关）
- 「我的」收藏条目 → 走长按删除同一套 `confirmRemove`（删接口 / 关详情 / 出列表 / 展架件数 −1 / `markCollectionDataStale()`）
- 心愿条目·未标记 → 拉起标记半窗

### 5. 处理页（`package-editor/pages/processing/index.vue`）

失败态原先只有「删除这次记录并退出」——一次**免费的裁剪失败**竟被迫删除整条收藏，且没有重试出口。新增：
- 「重试」：裁剪 / 抠图各自按端点重跑，沿用已保存裁剪参数
- 「返回编辑」：失败态也能回编辑页继续操作

## 八、开发规范提醒（本次踩到的坑）

### 1. 改了 Prisma schema 必须同时生成迁移

本轮给「调色」加了 `cropBrightness` / `cropContrast` / `cropSaturation` 三个字段，只改了 `schema.prisma`，**没有建迁移**。后果：

- 本地 `pnpm db:generate` 只重新生成 Client（类型层面有字段），数据库里并没有这些列
- 于是 `GET /api/collectibles` 一查就 500：`The column Collectible.cropBrightness does not exist`
- 表现是「我的」页面请求失败，而首页 feed 正常（它查 OfficialBag，不受影响）——很容易误判成前端问题

> 关键点：本地 `prisma migrate dev` 能自动发现差异，但 CI / 生产用的是 `migrate deploy`，**只应用已存在的迁移文件**。
> 所以「本地能跑」不代表线上能跑 —— schema 改动一定要提交对应的迁移文件。

已补迁移 `20261002051741_add_crop_color_adjustments`，内容：
- `Collectible` 增加三个调色列（可空 Double）
- `cropRotation` 由 integer 改为 Double（配合任意角度微调）
- 附带 `DROP INDEX "OfficialBag_brandId_idx"`：该索引在库里存在但 schema（含 main）从未定义，属历史遗留，Prisma 按对齐规则删除；官方袋子数量小，无性能影响

### 2. `.env` 是本地必需、不入库的

根目录 `.env`（从 `.env.example` 复制）缺失时，api 会在配置校验处直接退出，报 `DATABASE_URL / REDIS_URL / JWT_SECRET Required`。
注意 `.env.example` 里开发库密码写的是 `bagcollect`，但 `docker-compose.local.yml` 实际设的是 **`bagcollect_local`**，照抄会连不上库（`db:local:deploy` 脚本用的是正确值）。

### 3. 小程序 mock 构建需要 `.env.mock`

`pnpm build:miniapp:mock` 走 `uni build --mode mock`，需要 `apps/miniapp/.env.mock` 提供 `VITE_USE_MOCK=1` 与 `VITE_API_BASE_URL`。
该文件项目里没有，缺失时 `config.ts` 的 `VITE_API_BASE_URL is required` 会直接抛错导致白屏。已创建（被 `.gitignore` 的 `.env.*` 规则忽略，不入库）。
